## 一句话介绍

将“整场会议说了什么”转化为“我接下来要做什么”，并在遇到具体任务问题时，邀请带着会议上下文的专家 Agent 提供分析。

## 目标用户与问题

面向经常参与项目例会的产品、研发、运维和跨部门协作人员，尤其是需要从长纪要中确认自身责任与交付时间的执行者。

会议纪要通常混合了讨论、别人的任务、已完成事项和未明确的建议。参会者需要反复查找自己的安排，遇到专业问题时又要向他人重新解释背景。本项目先筛选与本人明确相关的任务，再让专家围绕选中的任务分析，减少重复阅读和背景整理。

## 核心使用流程

1. 输入本人在纪要中的姓名，粘贴纪要或导入 `.txt` / `.md`。
2. GPT 整理本人负责、协作和分工待确认的安排；用户核对截止时间与逐字引用的原文依据。
3. 选择任务，记录疑问；可自行处理，也可按需邀请运维、数据库、网络、安全、产品或自定义专家。
4. 添加专家只准备上下文，发送 `@专家` 后才触发模型回答。
5. 查看与任务关联的分析、参考依据和下一步建议，搜索历史记录并勾选任务完成状态。

## 核心功能

| 功能 | 已实现的交互 |
| --- | --- |
| 纪要导入 | 粘贴文本、文本文件导入、姓名填写、长度校验、失败重试 |

| 可用性 | 蓝色 @ 名称、输入 @ 才提示成员、固定记录搜索框、响应式布局、拖动字号、高对比主题 |

## Agent 与模型如何工作

前端维护原始纪要、任务、讨论和专家会话；Python 后端通过配置的 Responses 兼容接口调用 `gpt-6.1-sol`。任务提取与专家回答使用不同提示和返回结果校验。专家收到原文、任务信息与近期讨论，按指定角色回答；没有独立的外部工具调用或后台任务执行。

模型接口地址当前为 `https://api.openai-next.com/v1`，属于第三方兼容网关。模型和地址可由环境变量替换，具体可用模型取决于服务账号权限。项目未训练或部署自有基础模型。

## 当前边界与后续方向

目前是单用户、本地运行的原型。任务和问答保存在页面内存，刷新后清空；仅显示偏好持久化。支持文本纪要，不直接解析 PDF、Word 或音视频；不包含真实会议接入、登录、多用户同步和生产执行。建议动作可模拟确认，不会修改外部系统。

任务归属仍需人工核对，尤其是同名、别名和代词情况。后续可在保留原文追溯的基础上扩展存储、会议系统接入和正式任务管理集成。

## 可用于报名表的短介绍

ContextOps 是面向会议参与者的会后任务专家助手。用户导入纪要并填写姓名后，系统使用 GPT 整理本人负责、协作及待确认的任务，展示截止时间与原文依据。遇到任务难点时，可按需邀请不同领域专家，通过 @ 提问获得结合纪要和任务背景的分析，并搜索历史记录。项目已实现可运行的 Web 交互、模型接口、结果校验和失败重试，帮助用户从阅读纪要走向具体行动。
