# 代码与运行说明

## 交付代码

源码位于压缩包中的 `ops-context-agent/`。正式仓库 URL、分支和提交号尚待团队填写，见 `提交清单.md`。解压包能够独立启动，不依赖开发者电脑上的 Codex 配置文件。

## 环境依赖

| 项目 | 要求 |
| --- | --- |
| 操作系统 | Windows、Linux 或 macOS；主办方具体环境尚未提供 |
| Python | 3.9 或以上；本机验证版本为 3.9.2 |
| Python 运行依赖 | 仅标准库，无需安装第三方包 |
| 浏览器 | 建议当前版本 Edge 或 Chrome，启用 JavaScript |
| 模型服务 | 可连通的 Responses 兼容接口、有效 API key、账号有权限使用的模型 |
| 可选工具 | Node.js 仅用于脚本语法检查；Playwright 仅用于重新录屏；Docker 为备选启动方式 |

前端不依赖 npm 构建、CDN、远程图片或在线字体。真实任务提取与专家回答需要联网访问配置的模型服务。

## Windows PowerShell 启动

解压后进入源码目录（使用自己的实际路径）：

```powershell
cd .\ops-context-agent
$env:OPENAI_API_KEY = '替换为评审环境可用的密钥'
$env:OPENAI_BASE_URL = 'https://api.openai-next.com/v1'
$env:OPENAI_MODEL = 'gpt-6.1-sol'
python -u server.py
```

看到 `key_configured=True` 后访问 http://localhost:5175。该状态仅表示发现了密钥，不保证账号权限或网络正常。不要直接双击 `index.html`，否则无法访问后端接口。

## Linux / macOS 启动

```bash
cd ops-context-agent
export OPENAI_API_KEY='替换为评审环境可用的密钥'
export OPENAI_BASE_URL='https://api.openai-next.com/v1'
export OPENAI_MODEL='gpt-6.1-sol'
python3 -u server.py
```

浏览器访问 http://localhost:5175。如果主办方提供其他兼容服务，应使用它实际提供的 base URL 和模型名，不能仅凭名称假定可用。

## 可选 Docker 启动

仓库提供 Dockerfile，不需要 npm 或 pip 安装。

```bash
docker build -t contextops .
docker run --rm -p 127.0.0.1:5175:5175 --env-file .env contextops
```

运行前复制 `.env.example` 为 `.env`，填写可用密钥。这里 `.env` 由 Docker 读取；直接运行 `python server.py` 不会自动读取 `.env`。构建基础镜像需要网络或主办方已有的 `python:3.11-slim` 镜像。当前机器未安装 Docker，因此此方案尚未实机验证；标准 Python 启动是已验证路径。

## 配置项

| 变量 | 用途及默认值 |
| --- | --- |
| `OPENAI_API_KEY` | 模型密钥；建议在评审启动终端中显式设置 |
| `OPENAI_BASE_URL` | 覆盖 `model-config.json` 中的第三方兼容网关地址 |
| `OPENAI_MODEL` | 覆盖配置中的 `gpt-6.1-sol` |
| `HOST` | 默认 `127.0.0.1`；容器内设为 `0.0.0.0` |
| `PORT` | 默认 `5175`，更改后使用相应端口访问 |

本地开发还支持 Windows 用户/系统环境变量及 Codex 的认证文件作为密钥回退来源，但交付包不包含这些文件，评审复现不需要安装 Codex。密钥不在前端读取。

## 三分钟体验

1. 导入 `examples/meeting-demo.txt`，本人姓名填“周宁”，点击“提取我的任务”。
2. 预期出现需求清单、迁移验收协作、跨部门反馈待确认等本人相关任务。林晓独立的帮助文档任务、周宁已经完成的旧版校对不应列为新待办；模型措辞与排序可能不同。
3. 展开原文依据，确认周五/下周三等原文时间；分工含糊的任务应标记待确认。
4. 选中“数据库迁移验收”相关任务，点击“请专家协助”，选择数据库专家并添加。
5. 添加后不会调用问答接口；发送 `@数据库专家 请基于纪要列出验收关注点、还缺的信息和下一步安排。` 才生成分析。
6. 在右侧搜索“验收”，滚动回答记录，搜索框和参会专家保持可见；清空可恢复全部记录。勾选任务可标记完成。

## 验证命令

```powershell
python -m unittest discover -s tests -v
node --check app.js
node --check minutes.js
```

已有交付压缩包时，可以执行 `python tools/verify_submission.py`：校验文件摘要，解压到临时目录运行测试，并用占位密钥验证独立启动、静态文件与接口参数校验。该检查不调用真实模型，不使用开发者的认证文件。

单元测试使用模拟模型响应，验证原文与本人归属、异常结果、路由隔离和请求参数，不消耗模型额度。真实联调另见 `验证记录.md`，二者不能互相替代。

## 常见问题

| 现象 | 处理方法 |
| --- | --- |
| 密钥未找到 | 在启动服务的同一终端显式设置环境变量后重启；`.env` 文件不会自动加载 |
| POST 返回 502 | 查看页面错误；检查账号、模型权限、接口地址、额度、代理和网络；失败可重试，不会改用假回答 |
| 浏览器能联网但服务超时 | Python 进程也需要可用的网络代理；按运行环境设置 `HTTPS_PROXY` 后重启 |
| 无本人任务 | 姓名应与纪要原文一致；仅相关岗位或未点名的事项不会自动归属本人 |
| 端口占用 | 停止已占用的服务，或设置 `PORT` 使用其他端口 |
| 页面刷新后记录丢失 | 当前版本按页面会话保存，重新导入即可；不包含历史存储 |

## 目录与接口

```text
index.html / styles.css       页面结构与样式
minutes.js                   导入、任务卡片和选中任务
app.js                       讨论、专家角色、@ 和问答记录
server.py                    静态服务与模型请求
model-config.json            不含密钥的模型默认配置
tests/test_minutes.py        后端单元测试
examples/meeting-demo.txt    虚构演示纪要
docs/                        交付说明、视频与截图
tools/                       演示录制与交付包生成脚本
```

- `POST /api/minutes`：输入 `{person, minutes}`，返回会议摘要和本人任务。
- `POST /api/chat`：输入专家角色、问题、上下文，返回回答、依据标签和建议动作。
- 两类请求经服务端发送到配置的 `/responses`，使用 `store=false`。该参数不能代替第三方服务的数据政策。

组件来源与沿用情况见 `组件来源.md`。
